# 摸鱼成就系统 & 统计功能 · 需求文档（PRD）

> 作为新功能集成进现有「宜忌月历 · 摸鱼账本」。范围**仅限摸鱼相关**数据（健康提醒的成就/统计本期不做）。
> 落地范围：**网页版（根目录 index.html）+ Chrome 扩展版（extension/）都做**，两版功能一致。
> 设计原则：KISS / YAGNI / DRY —— 零新增数据采集，全部指标从既有 `moyu-log` 回溯计算。

## 1. 背景与目标

现有产品已按天记录摸鱼时长（`moyu-log:YYYY-MM-DD`）与薪资模型（`moyu-settings`）。本功能在**不新增任何埋点**的前提下，把这些沉睡的历史数据变成：

- **统计面板**：让用户直观看到"我到底摸了多少、省了多少、坚持了多久"。
- **成就系统**：用可解锁的徽章给予正反馈，增强趣味与粘性。

**核心价值**：把已有数据可视化 + 游戏化激励，几乎零采集成本。

## 2. 数据来源盘点（复用，零新增采集）

| 数据 | 键 | 网页版存储 | 扩展版存储 | 含义 |
|---|---|---|---|---|
| 逐日摸鱼时长 | `moyu-log:YYYY-MM-DD` | localStorage | chrome.storage.local | 当日累计秒数 |
| 薪资模型 | `moyu-settings` | localStorage | chrome.storage.local | 时薪/月薪，用于换算金额 |

**关键前提**：所有统计指标与成就判定都能从上述两键**回溯计算**，历史数据天然存在。两版**键名与语义完全一致**，仅读写 API 不同（同步 localStorage vs 异步 chrome.storage.local）——因此**纯计算逻辑可完全复用**，只需各自适配一层"取数"函数。

## 3. 名词与约定

| 名词 | 含义 |
|---|---|
| 打卡日 | 当日 `moyu-log` 存在且秒数 > 0 的日期 |
| 连续打卡 | 从某日往前连续每天都是打卡日的最长天数 |
| 当前连击 | 从今天（或最近打卡日）往回的连续打卡天数 |
| 成就 | 一条声明式规则（指标 + 阈值），指标达标即解锁 |
| 解锁动画 | 首次达标时的祝贺提示（仅展示一次） |

## 4. 统计功能需求

### 4.1 派生指标（全部由逐日 log 计算）

| 指标 | 计算方式 |
|---|---|
| 累计摸鱼时长 | 所有 `moyu-log:*` 秒数求和 |
| 累计省下的钱 | 总秒数 × 时薪 ÷ 3600 |
| 打卡总天数 | 秒数 > 0 的日期数 |
| 当前连续打卡 | 从今天往回连续打卡天数 |
| 历史最长连续 | 遍历全部日期求最长连续段 |
| 单日最高纪录 | max(逐日秒数) 及其日期 |
| 日均摸鱼时长 | 总秒数 ÷ 打卡天数 |
| 近 7 / 30 天小计 | 按日期范围过滤求和 |

### 4.2 可视化

| 元素 | 规格 |
|---|---|
| 数字卡片区 | 累计时长、省下的钱、打卡天数、当前连击、最长连击、单日最高 |
| 近 30 天柱状条 | 纯 CSS 高度条（不引第三方图表库），每根代表一天摸鱼时长；无数据日为空 |

> 决策：先做**近 30 天简单柱状条**，不做日历热力图（YAGNI，后续需要再升级）。

## 5. 成就系统需求

### 5.1 判定原则：无状态、可重算

- 不持久化"是否解锁"，每次打开面板**根据当前指标实时判定**（`指标值 >= 阈值` 即解锁）。
- 好处：无一致性问题；卸载重装只要 `moyu-log` 还在即可恢复；新增成就零逻辑改动。
- **唯一需要持久化的**：`moyu-achievements-seen`（已展示过解锁动画的成就 id 数组），用于避免重复弹祝贺。

### 5.2 成就清单（初版）

| 类别 | 成就 | 解锁条件（指标 ≥ 阈值） |
|---|---|---|
| 累计时长 | 摸鱼学徒 / 摸鱼老手 / 摸鱼大师 | 累计 1h / 10h / 100h |
| 连续打卡 | 三天打鱼 / 一周不辍 / 月度鱼王 | 当前连击 3 / 7 / 30 天 |
| 单日纪录 | 今日超神 | 单日最高 ≥ 4h |
| 省钱 | 小赚一笔 / 回本了 | 累计省下 ¥100 / ¥1000 |

> 说明：具体成就名/文案可在实现阶段微调。数量与阈值遵循"够用即可"，不做投机性扩展。

### 5.3 成就声明结构（内置常量，声明式）

```js
ACHIEVEMENTS = [
  { id: 'time-1', name: '摸鱼学徒', desc: '累计摸鱼满 1 小时', icon: '🐟',
    metric: 'totalSeconds', threshold: 3600 },
  // ...
];
// 判定：computeMetrics(logs, settings)[a.metric] >= a.threshold
```

新增成就只需追加一条声明（DRY）。

## 6. 明确不做（本期范围外）

1. **健康提醒相关成就/统计**（喝水/起身/看远/深呼吸）——本期不做。
2. **时段类成就**（早起摸鱼 / 深夜党）——现有 log 只按天聚合，**未记录摸鱼发生的具体时刻**，需新增按小时埋点，属额外采集，本期不做。
3. **日历热力图**——先用近 30 天柱状条替代。
4. **跨设备/云端同步的成就进度**——沿用现有本地存储，不引入。

## 9. 验收标准

1. 有历史 `moyu-log` 数据时，打开面板能正确显示累计时长/省钱/打卡天数等指标。
2. 连续打卡天数计算正确（含跨月、含今天未摸鱼时的边界）。
3. 达标成就显示为已解锁，未达标显示为锁定态（可展示进度）。
4. 首次达成某成就弹一次祝贺，再次打开不重复弹。
5. 无任何历史数据时，面板显示为空态而非报错。
6. 网页版与扩展版展示与计算结果一致。
