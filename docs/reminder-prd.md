# 喝水提醒 · 需求文档（PRD）

> 喝水提醒的核心（chrome.alarms、chrome.scripting 注入、chrome.notifications）全部依赖 Chrome 扩展 API，网页版（纯 index.html）根本没有这些 API，无法实现同样的后台提醒。
> 所以这个功能本质上只能存在于 extension/，网页版无对应实现。这与"双份同步"约定不冲突——同步只适用于两边都存在的共享模块（如 moyu-timer.js），而喝水提醒是扩展独有能力。

> 作为新功能集成进现有 Chrome 扩展「宜忌月历 · 摸鱼账本」。
> 面板方案：**DOM 浮层为主 + 系统通知兜底**。分两个迭代交付：**V1（MVP）** 先跑通核心闭环，**V2** 补齐防打扰与高级体验。

## 1. 背景与目标

现有扩展是「摸鱼计时/记账」工具，已具备 MV3 Service Worker + `chrome.alarms` 的后台能力。本功能在其基础上新增「定时提醒喝水/休息」：到点在**当前网页右下角**弹出一个轻量小面板，提供「稍后提醒 / 关闭」两个操作，不抢夺页面焦点。

**核心价值**：温柔提醒、即点即走、尽量不打断用户当前的操作。

## 2. 名词与约定

| 名词 | 含义 |
|---|---|
| 提醒周期 | 用户设定的两次提醒之间的间隔（默认 30 分钟） |
| 提醒面板 | 到点后展示的右下角小窗（DOM 浮层，兜底时降级为系统通知） |
| 稍后（Snooze） | 临时打断，5 分钟后再弹一次，不影响原周期 |
| 关闭（Dismiss） | 结束本次，按原间隔重新开始下一周期计时 |

## 4. V1（MVP）详细需求

### 4.1 设置项（在现有 popup.html 中新增「喝水提醒」区）

| 配置项 | 控件 | 说明 |
|---|---|---|
| 提醒间隔 | 下拉：5 / 15 / 30 / 60 分钟 / 自定义（分钟输入框） | 默认 30。修改后立即生效并重置计时。自定义最小 1 分钟。 |
| 启用/禁用 | 开关 | 关闭后暂停所有提醒；再次开启从头开始计时（不延续进度）。 |
| 提示音 | 开关 | 开启时弹面板伴随极短「叮」（< 0.5s）。默认开启。 |

### 4.2 计时核心

- 使用 `chrome.alarms` 周期触发（**独立于**摸鱼计时的 alarm），精度允许 ±1 秒。
- 间隔与开关存 `chrome.storage.sync`（可跨设备同步）；运行态存 `chrome.storage.local`。

### 4.3 提醒面板（DOM 浮层）

| 属性 | 规格 |
|---|---|
| 尺寸 | 宽 280px，高自适应（约 120–150px） |
| 位置 | 当前网页右下角，距边缘 20px |
| 层级 | 极高 z-index，`pointer-events` 仅作用于面板自身；不劫持页面键鼠焦点 |
| 内容 | ① 当前时间 ② 固定文案「该喝口水啦 👀」 ③ 两个按钮 |
| 关闭方式 | 点击面板外部**不关闭**（防误触），仅按钮操作 |

### 4.3.1 提醒目标标签页（多标签 / 多窗口）

提醒触发时**只在「最后聚焦的浏览器窗口里、当前正在看的那个标签页」弹出浮层**（即 `lastFocusedWindow` + `active` 的唯一标签页），一次只注入一个，不会在所有标签页同时弹。

| 场景 | 行为 |
|---|---|
| 多个标签页 | 仅**当前激活可见**的那一个弹浮层，后台其它标签页不弹 |
| 多个浏览器窗口 | 选**最近获得焦点**的那个窗口的活动标签页 |
| 目标页无法注入（`chrome://`、网上应用店、PDF 等） | 降级为**系统通知**（系统通知属浏览器级，与具体标签页无关） |
| 触发瞬间用户切了标签页 | 以 alarm 触发那一刻的查询结果为准，弹在切过去后的活动页 |
| 触发时浏览器无聚焦窗口（最小化/切到别的应用） | 仍向最近聚焦过的浏览器窗口的活动页注入浮层；用户未在看浏览器时可能不会立刻注意到（V1 不特殊处理，保持此行为） |


### 4.4 按钮逻辑

| 按钮 | 行为 | 后续 |
|---|---|---|
| 稍后（Snooze） | 关面板，创建 5 分钟后的**单次** alarm | 5 分钟后再弹同款面板；若再点稍后，再次重置为 5 分钟 |
| 关闭（Dismiss） | 关面板，取消当前 alarm，按原间隔重建**周期** alarm | 按设定间隔（如 30 分钟）进行下一次 |

**关键区别**：稍后=临时延后 5 分钟；关闭=结束本周期、下周期按原计划。

### 4.5 兜底策略（MVP 必须有）

当当前标签页无法注入 DOM 浮层（`chrome://`、Chrome 网上应用店、PDF 查看器、无活动标签页等）时：**降级为 `chrome.notifications` 系统通知**，同样提供「稍后 / 关闭」两个按钮，逻辑与面板一致。

## 5. V2 增强需求（防打扰）

> 实现状态：**V2 已全部实现**（2026-08-06）。存储契约新增：`water-settings` 增 `quietEnabled/quietStart/quietEnd`；`water-whitelist`（sync 域名数组）；`water-stats`（local 今日 提醒/稍后/关闭，跨天重置）；`water-snooze-log`（local 稍后 15 分钟滑窗）；`water-runtime.mode` 增 `retry/pause`。

| 场景 | 处理方式 | 实现要点 |
|---|---|---|
| 全屏（视频/PPT） | 检测到 `document.fullscreenElement`，不弹；退出全屏 10 秒后再弹 | content-reminder.js 自行监听 `fullscreenchange`，退出后 10s 渲染；期间再进全屏则重置等待 |
| 正在输入 | 焦点在 `input/textarea/[contenteditable]` 时，延迟 1 分钟后重试 | content 回传 `water-defer:input`，后台建 1 分钟单次 `retry` alarm |
| 频繁稍后 | 15 分钟内连续「稍后」≥ 3 次，面板多一行「看起来不方便？点『暂停 1 小时』」 | 后台 `water-snooze-log` 滑窗计数，达阈值时 `water-show` 带 `showPauseHour`；点击回传 `water-pause-1h` 建 60 分钟 `pause` alarm，到点恢复周期 |
| 白名单网站 | 指定域名（如 youtube.com）自动暂停提醒 | 后台 `fireReminder` 查活动页 host，子域名匹配命中则跳过本次；popup textarea 每行一个域名 |
| 每日静音时段 | 设定时间段内不提醒 | 后台 `inQuietHours()` 支持跨午夜（22:00–08:00）；popup 开关 + 起止时间 |
| 统计面板 | popup 显示今日 提醒/稍后/关闭 次数 | 后台 `bumpStat`（浮层回传 `water-shown` 或通知成功→remind；snooze/dismiss 同理），popup 读 `water-stats` 并随 `storage.onChanged` 实时刷新 |

## 6. V1 交互流程

```
用户设置间隔（如 30min）→ 启用
        ↓
background 创建周期 alarm（每 30min）
        ↓
alarm 触发
        ↓
向当前标签页注入 DOM 浮层
        ├── 注入成功 → 右下角面板（不抢焦点）+ 可选"叮"
        └── 注入失败 → 系统通知兜底
        ↓
   ┌────┴────┐
【稍后】     【关闭】
   ↓          ↓
关面板       关面板
建 5min 单次  取消当前 alarm
alarm        重建 30min 周期 alarm
   ↓          ↓
5min 后弹    30min 后弹
```

## 7. 已知限制（务必知悉）

- DOM 浮层只能作用于**已注入的当前标签页**；切到未注入的页看不到面板（此时靠系统通知兜底或下次注入）。
- `chrome://`、网上应用店、部分 PDF、跨域 iframe 无法注入，只能走通知兜底。
- 全屏/输入检测依赖注入的 content script，兜底通知场景下不具备这些检测。

## 8. V1 验收标准

1. 设置 5 分钟间隔并启用 → 5 分钟后普通网页右下角出现面板。
2. 点「稍后」→ 面板消失，5 分钟后再次出现。
3. 点「关闭」→ 面板消失，30 分钟（或设定值）后按原周期再次出现。
4. 关闭浏览器再打开 → 间隔与开关设置保持不变。
5. 在 `chrome://extensions` 页触发 → 出现系统通知而非报错。
6. 提示音开关生效：关闭后弹面板无声。
